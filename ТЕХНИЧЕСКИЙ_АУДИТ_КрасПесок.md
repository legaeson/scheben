### 1.3. INP (Interaction to Next Paint) и микрофризы при скролле
- **Статус:** ⚠️ Замечание
- **Уровень риска:** 🟡 Средний
- **Файл:** `public/app.js`, строки 376–395 и 405–437
- **Проблема:** В функциях `setupScrollSpyAndBackToTop()` и `setupMobileStickyCtaBehavior()` обработчики события `scroll` вызываются синхронно при каждом пикселе прокрутки.
  Внутри них циклически опрашиваются свойства разметки, вызывающие принудительный перерасчет геометрии (Layout Thrashing / Reflow):
  ```javascript
  // app.js:383 — опрос offsetTop в цикле на каждый тик скролла
  sections.forEach(sec => {
      const secTop = sec.offsetTop - 120;
      if (window.scrollY >= secTop) { ... }
  });

  // app.js:418 — вызов getBoundingClientRect() на каждый тик скролла
  const rect = orderSection.getBoundingClientRect();
  ```
  На смартфонах со слабым процессором это приводит к просадке частоты кадров (FPS drop) при быстром скролле.
- **Решение:** Использовать `IntersectionObserver` для определения видимости секций или обернуть scroll-обработчик в `requestAnimationFrame`:
  ```javascript
  let isScrolling = false;
  window.addEventListener('scroll', () => {
      if (!isScrolling) {
          window.requestAnimationFrame(() => {
              updateVisibility();
              isScrolling = false;
          });
          isScrolling = true;
      }
  }, { passive: true });
  ```

### 1.4. Политика кэширования и кэш-инвалидация HTML
- **Статус:** ⚠️ Требует исправления
- **Уровень риска:** 🟡 Средний
- **Файл:** `server.js`, строки 40–52
- **Проблема:** В `server.js` статика настроена с параметром `maxAge: '7d'`:
  ```javascript
  app.use(express.static(PUBLIC_DIR, {
      dotfiles: 'ignore',
      index: 'index.html',
      maxAge: '7d',
      setHeaders: (res, filePath) => {
          if (/\.(webp|avif|jpg|jpeg|png|svg|ico)$/i.test(filePath)) {
              res.setHeader('Cache-Control', 'public, max-age=31536000, immutable');
          }
      }
  }));
  ```
  Если файл не попадает под регулярное выражение (например, `index.html`), он наследует глобальный `maxAge: '7d'` (`Cache-Control: public, max-age=604800`).
  В результате браузер кэширует сам HTML-файл на неделю, и при публикации правок на сервере вернувшиеся пользователи не увидят обновленный сайт до истечения 7 дней или ручной очистки кэша.
- **Решение:** Для HTML-файлов всегда явно устанавливать `no-cache`:
  ```javascript
  if (/\.html$/i.test(filePath)) {
      res.setHeader('Cache-Control', 'no-cache, must-revalidate');
  }
  ```

### 2.2. Защита от спама и DDoS (Rate Limiting)
- **Статус:** ⚠️ Частично
- **Уровень риска:** 🟡 Средний
- **Файлы:** `server.js:46-55`, `deploy/nginx.conf`
- **Проблема:**
  1. В Express настроен строгий лимитер для оформления заказов (не более 5 заявок за 10 минут с одного IP). Это отлично защищает от спама диспетчера.
  2. Однако в `deploy/nginx.conf` **отсутствует ограничение частоты запросов** (`limit_req_zone`).
     При атаке HTTP-флудом (DDoS) на корень `/` или статические файлы Nginx будет без ограничений перенаправлять трафик на процесс Node.js, что может вызвать перегрузку однопоточного цикла событий (Event Loop) Express.
- **Рекомендация:** Добавить в `deploy/nginx.conf` в блок `http`:
  ```nginx
  limit_req_zone $binary_remote_addr zone=req_limit:10m rate=15r/s;
  limit_conn_zone $binary_remote_addr zone=conn_limit:10m;
  ```
  И в блоке `server`:
  ```nginx
  limit_req zone=req_limit burst=30 nodelay;
  limit_conn conn_limit 20;
  ```

### 2.5. Файловое хранилище и Docker Bind-Mount Gotcha
- **Статус:** ⚠️ Архитектурный риск в Docker
- **Уровень риска:** 🔴 Высокий (при запуске в контейнере)
- **Файлы:** `server.js:69-73`, `deploy/docker-compose.yml:14-15`
- **Проблема:**
  В `server.js` функция `atomicWriteFileSync` реализует атомарную запись:
  ```javascript
  function atomicWriteFileSync(filePath, content) {
      const tempPath = `${filePath}.${Date.now()}.${crypto.randomBytes(4).toString('hex')}.tmp`;
      fs.writeFileSync(tempPath, content, 'utf8');
      fs.renameSync(tempPath, filePath);
  }
  ```
  В `docker-compose.yml` файлы смонтированы как одиночные bind-mounts:
  ```yaml
  volumes:
    - ./orders.json:/app/orders.json
    - ./orders.md:/app/orders.md
  ```
  В ОС Linux системный вызов `rename()` над точкой монтирования отдельного файла завершается фатальной ошибкой:
  `EXDEV: cross-device link not permitted` или `EBUSY: resource busy or locked`.
  При работе в Docker сохранение заявок может аварийно упасть!
- **Решение:**
  Либо монтировать каталог целиком (например, `- ./data:/app/data`), либо предусмотреть в коде fallback при ошибке переименования:
  ```javascript
  function atomicWriteFileSync(filePath, content) {
      const tempPath = `${filePath}.${Date.now()}.${crypto.randomBytes(4).toString('hex')}.tmp`;
      try {
          fs.writeFileSync(tempPath, content, 'utf8');
          fs.renameSync(tempPath, filePath);
      } catch (err) {
          // Fallback для сред с ограничениями на rename (Docker bind mounts)
          fs.writeFileSync(filePath, content, 'utf8');
          if (fs.existsSync(tempPath)) {
              try { fs.unlinkSync(tempPath); } catch (e) {}
          }
      }
  }
  ```

## РАЗДЕЛ 4. ДОСТУПНОСТЬ (ACCESSIBILITY / WCAG 2.1) И МОБИЛЬНЫЙ UX

### 4.1. Метатег Viewport и блокировка масштабирования
- **Статус:** 🔴 Нарушение WCAG 2.1 (Критерий 1.4.4 Resize Text)
- **Уровень риска:** 🔴 Высокий (влияет на оценку Google Lighthouse Accessibility)
- **Файл:** `public/index.html`, строка 5
- **Проблема:**
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
  ```
  Параметры `maximum-scale=1.0, user-scalable=no` принудительно запрещают пользователям мобильных устройств увеличивать страницу жестом pinch-to-zoom.
  Это грубое нарушение требований доступности для людей с ослабленным зрением. Поисковые системы пенализируют сайты с заблокированным зумом при оценке мобилопригодности.
- **Решение:** Заменить на стандартный адаптивный тег:
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  ```

  При ручном редактировании файлов в корне изменения не попадут в браузер, пока они не скопированы в `public/`.
- **Рекомендация:** Настроить единый источник правды (Single Source of Truth) — вести разработку строго в `public/`, а корень очистить от дубликатов либо настроить build-скрипт в `package.json`.

## РАЗДЕЛ 6. ИНФРАСТРУКТУРА И ДЕПЛОЙ (DEVOPS)

### 6.1. Раздача статики через Nginx против Node.js
- **Статус:** ⚠️ Рекомендация по оптимизации архитектуры
- **Уровень риска:** 🟢 Низкий
- **Файл:** `deploy/nginx.conf`, строки 41–45
- **Проблема:**
  Сейчас в Nginx блок отдачи картинок проксирует запрос обратно в Node.js:
  ```nginx
  location /images/ {
      proxy_pass http://127.0.0.1:2000/images/;
      expires 365d;
  }
  ```
  Node.js тратит ресурсы однопоточного Event Loop на отдачу статических файлов.
- **Решение:** Nginx должен отдавать статику напрямую из файловой системы:
  ```nginx
  location /images/ {
      root /var/www/kraspesok/public;
      expires 365d;
      add_header Cache-Control "public, max-age=31536000, immutable";
      access_log off;
  }
  ```

### 6.2. Права доступа в Systemd Unit
- **Статус:** ⚠️ Риск сбоя при деплое
- **Уровень риска:** 🟡 Средний
- **Файл:** `deploy/kraspesok.service`, строки 7–9
- **Проблема:**
  Сервис запускается от пользователя `User=www-data`.
  Если рабочий каталог `/var/www/kraspesok` развернут из git под пользователем `root` или обычным пользователем, процесс Node.js упадет с ошибкой `EACCES: permission denied` при первой попытке записать поступивший заказ в `orders.json` или создать резервную копию в `./backups`.
- **Рекомендация:** В инструкцию по развертыванию включить команду назначения прав:
  `chown -R www-data:www-data /var/www/kraspesok`
